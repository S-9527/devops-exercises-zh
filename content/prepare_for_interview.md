<a name="how-to-prepare-for-devopssreproduction-engineer-interviews"></a>
## 如何准备 DevOps/SRE/生产工程师面试？
 
注：以下内容纯属个人观点。
 
<a name="skills-you-should-have"></a>
### 你应该具备的技能
 
<a name="linux"></a>
#### Linux
 
每个 DevOps 工程师应该对至少一种操作系统有深入的了解，如果你可以选择，那么我想说它绝对应该是 Linux 因为我相信这是至少 90% 的人的要求 DevOps 那里有招聘信息。此外， Linux 几乎是任何子区域或域的组成部分 DevOps 比如云、容器等。
 
通常，接下来的问题是“我的知识应该有多广泛？”从所有的 DevOps 技能，我想说这个和编码一样应该是你最强的技能。熟悉 OS 进程、调试工具、文件系统、网络……了解您的操作系统，了解它是如何工作的，如何解决问题等。

不久前，我创建了一个列表 Linux 资源权 [这里](https://dev.to/abregman/collection-of-linux-resources-3nhk)。那里有一些不错的网站，您可以使用它们来了解更多信息 Linux.
 
<a name="programming"></a>
#### 编程
 
我个人的信念是任何 DevOps 工程师应该懂得编程，至少在某种程度上。拥有这项技能，您可以自动化手动流程，改进您当前使用的一些开源工具或构建新的工具和项目来为现有问题提供解决方案。知道如何编码=强大的力量。

在面试时，您会注意到知识水平很大程度上取决于您面试的公司或职位。有些只要求您能够编写简单的脚本，而另一些则需要您深入研究复杂的算法和数据结构。

练习这项技能的最佳方法是进行一些实际的编码——脚本、在线挑战、 CLI 工具、网络应用程序……只是代码:)

另外，大多数人可能都清楚以下内容，但我们仍然要澄清一下：当有机会选择任何语言来回答编码任务/问题时，请选择您有经验的语言！有些候选人更喜欢选择他们认为公司正在使用的语言，这是一个巨大的错误，因为无论您使用哪种语言，给出正确的答案总是比错误的答案更好:)
 
我推荐以下网站来练习编码：
                                                 
* [黑客排名](https://www.hackerrank.com)
* [Leet代码](https://leetcode.com)               
* [练习](https://exercism.io)
 
开始自己的项目也是一个好主意。稍后会详细介绍。

<a name="architecture-and-design"></a>
#### 架构与设计
  
这也是一个重要的方面 DevOps。您应该能够描述如何设计不同的系统、工作流程和架构。此外，规模也是其中的一个重要方面。可能适用于十几个主机或 X 数据量的设计，不一定适用于更大的规模。
 
一些想法供您探索： 
                               
* 如何设计和实现 CI 用于验证 PR 的管道（或多个管道），运行多种不同类型的测试，打包项目并将其部署到某个地方
* 如何设计和实施安全 ELK 将从 10,000 个应用程序获取日志并最终向用户显示数据的架构
* 微服务设计现在也很流行

一般来说，您应该能够描述您执行的一些设计、项目、架构……。

<a name="tooling"></a>
#### 工装

有些采访将重点关注特定的工具或技术。哪些工具？这主要基于您在简历中提到的内容以及职位发布中提到的并在公司中使用的内容的组合。我相信任何人都应该知道以下一些关于他/她熟悉的工具的问题：
                               
* 该工具有什么作用？它使我们能够实现哪些没有它就无法实现的目标？                            
* 与同一领域、同一目的的其他工具相比，它的优势是什么？为什么你专门使用它？
* 它是如何运作的？
* 如何使用？
* 使用时应用/使用的最佳实践
                               
让我们深入探讨实际的准备步骤
                               
<a name="scenarios-challenges-tasks"></a>
### 场景 || 挑战 || 任务              
                               
这是当今面试的一种非常常见的方式 DevOps 角色。候选人被给予一项代表共同任务的任务 DevOps 工程师或某项常识和候选人有几个小时或几天的时间来完成任务。<br>
                               
这是准备面试的好方法，我建议在实际面试之前尝试一下。如何？从工作岗位中获取需求并将其转化为场景。让我们看一个例子：
                               
“知识在 CI/CD" -> 场景：创建一个 CI/CD 项目的管道。
                               
说到这里，有人问：“但是什么项目呢？”答案是：怎么样 GitHub？它只有 9125912851285192 个项目...以及免费的设置方式 CI 给他们中的任何一个（也是学习如何与他人合作的好方法:)）
                               
我们换个场景：

“配置服务器的经验”-> 场景：配置服务器（为了让它更有趣：创建一个 Web 服务器）。

最后一个例子：                                                                                                                                                        
“脚本编写经验”-> 场景：编写脚本。不要浪费太多时间思考“我应该写什么脚本？”。只需自动化您手动执行的操作，甚至实现您自己的常见小型实用程序版本。
  
<a name="start-your-own-devops-project"></a>
### 开始你自己的 DevOps 项目
  
开始一个 DevOps 项目是一个好主意，因为：
  
* 它会让你练习编码
* 您可以将其添加到简历中并与面试官讨论
* 取决于大小和复杂性，它可以教您一些有关设计的一般知识
* 根据采用情况，它可以教您如何管理开源项目
  
同样，不要过度思考你的项目应该是关于什么的。去构建一些东西吧:)
  
<a name="sample-interview-questions"></a>
### 面试问题示例
  
制作关于技术、公司、角色等各种主题/领域的面试问题样本列表，并尝试回答它们。
看看你是否能以流利、详细的方式回答他们。
  
更好的是，请一位好朋友/同事向您提出一些问题。您的自我意识可能会成为客观自我审查您的知识的障碍:)

对于那些参加技术聚会和会议的人来说，这可能是一个与其他公司的人员讨论面试过程的绝佳机会。但不要从它开始，这可能会很尴尬。至少先打个招呼吧……（：
  
这样做可以为您提供大量有关某些公司面试的期望或如何更好地准备的信息。
  
<a name="know-your-resume"></a>
### 了解你的简历
  
这听起来可能微不足道，但这里的想法很简单：准备好回答有关简历中任何一行的任何问题。
有时，当候选人被问及似乎与职位无关的技能或专业时，他们会感到惊讶，但简单的事实是：如果您在简历中提到了某些内容，那么询问您相关问题是公平的。

<a name="know-the-company"></a>
### 了解公司

熟悉您要面试的公司。一些想法：

  * 公司是做什么的？
  * 它有什么产品？
  * 为什么它的产品是独一无二的（或者比其他产品更好）？这也是一个值得你问的好问题

<a name="books"></a>
### 书籍

根据我的经验，许多候选人并没有这样做，但这是深入研究操作系统、虚拟化、规模、分布式系统等主题的最佳方法之一。    

在大多数情况下，你不读书也能做得很好，但 AAA 面试（最难的级别），如果你能激励自己变得更好，你会想要读一些书，总的来说 DevOps 工程师，书籍（还有文章、博客文章）是自我发展的好方法:)

<a name="consider-starting-in-non-devops-position"></a>
### 考虑从非DevOps 位置

虽然不是准备步骤，但您应该知道着陆 DevOps 作为第一位置可能具有挑战性。不，这并非不可能，但仍然如此，因为 DevOps 涵盖许多不同的实践、工具……对于尝试并实现这一目标的人来说，这可能是相当具有挑战性的，也是令人难以承受的。<br>
成为一名可能的途径 DevOps 工程师是从实际上不同（但相关）的职位开始，并在 1-2 年后或更长时间后从那里切换。

一些想法：

* 系统管理员 - 这是完美的，因为每个 DevOps 工程师应该对 OS 系统管理员知道他们的 OS :)
* 软件开发人员/工程师 - A DevOps 应该具备编码技能，并且在大多数情况下，该职位将提供超出所需的知识
* QA 工程师 - 这是一个更棘手的问题，因为 IMHO 重叠领域/技能较少 DevOps 工程师。当然， DevOps 工程师应该有一些关于测试的知识，但通常，他们的扎实技能/背景似乎主要由系统内部结构和编码技能组成。
                                                                           
<a name="what-to-expect-from-a-devops-interview"></a>
### 可以期待什么 DevOps 面试？                                
                                                                           
DevOps 面试可能会有很大不同。有些会包括设计问题，有些会集中于编码，有些会包括简短的技术问题，你甚至可能会接受面试，面试官只会浏览你的简历并讨论你过去的经验。
                                                                           
您可以采取一些措施来避免这种令人难以承受的体验：
                                                                           
1. 您可以而且可能应该询问 HR （在某些情况下甚至是团队负责人）面试过程是怎样的。有些人甚至会很友善地告诉您如何准备。
2. 通常，招聘启事不仅仅是暗示重点在哪里以及您在准备过程中应该关注的内容，因此请仔细阅读。
3. 有很多网站都有不同公司（尤其是大企业）面试过程的笔记或摘要。
                                                                           
<a name="dont-forget-to-be-an-interviewer-as-well"></a>
### 别忘了也成为面试官                              
                                                                           
有些人倾向于将面试视为“确定候选人是否合格”的单向道路，但实际上，候选人还应该确定是否合格。
他/她正在面试的公司是适合他/她的地方。            
                                                                                                                 
* 我关心团队规模吗？更具体地说，我关心的是成为一个人的表演还是成为一个更大团队的一部分？
* 我关心工作与生活的平衡吗？                                       
* 我关心个人成长以及如何实际实现它吗？           
* 我是否关心了解作为该角色的一部分我的职责是什么？                                                                                                  
如果你这样做，你也应该扮演面试官的角色:)
